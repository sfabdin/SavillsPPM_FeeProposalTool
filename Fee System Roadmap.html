Fee & Revenue System.
Phased roadmap.

The single entry point for every fee Savills PPM develops — built once in the calculator, then flowing downstream to projections, billing, accruals, flash reports and P&L. Capture the number where it's born, and stop re-keying it across fifteen spreadsheets.

01

Capture the fee where it's born.

Every fee starts as a matrix someone builds in the calculator. That's the source of truth — roles, rates, discount, phase split, monthly schedule. Authored once, saved to the database, and never typed into a spreadsheet again. You can't send a fee without it, so the data is captured by definition.

02

Let one number flow downstream.

That same record drives everything that comes after — monthly billing projections, accruals, the flash report, the P&L, fee-share splits, and the Salesforce intake. One number, entered once, reconciled everywhere. The output isn't just reporting to leadership; it's easing the burden on every leg of the process.

Decision · Storage

Where the data lives.

Honest tradeoffs · don't over-engineer Phase 1
Superseded

Browser localStorage + JSON file

Original single-user prototype
  • Shipped immediately, zero IT involvement
  • Worked offline, no API keys
  • JSON export = portable backup
  • Single browser, single user — no concurrent access
  • Cache clear destroyed data unless backed up
  • No permissions — replaced by Box (see right)
Today · Live

Box + OAuth (in production)

Multi-user, shared, permissioned
  • Sign in with Box — the app pulls data from a shared Box folder
  • Auto-sync: edits save locally, push to Box in the background
  • Fail-closed access: admins see all, others see only their own / granted projects
  • Confidential rate grid stays in Box, never in the deployed app
  • Booked records carry frozen $ snapshots Power BI reads directly
  • Per-person isolation is client-side — Box folder permission is the true wall
  • Server-side per-user filtering is the next hardening step
Future

Server auth for reporting

Unattended Power BI / Clockify pulls
  • Box service account reads the data with no human logged in
  • Server-side per-user filtering for true project-level isolation
  • Scheduled, hands-off reporting refresh
  • Needs a Box admin to provision the service account

Watch-outs

Risks & how we mitigate.

Backtracking is a slog.

50–100 historical projects, each with roles + rates + phases + FTE matrices, is a real chunk of work — even with LLM extraction.

Mitigation:   Pilot with 10 manual entries to prove the schema, then unlock the ingestion studio for the rest. Two PEs × 1 hr/week × 8 weeks gets us to 50+.

LLM extraction will hallucinate.

Claude will get rates wrong, miscount FTE %, or fabricate roles on edge-case docs.

Mitigation:   Every extraction is reviewed in side-by-side UI before save. Confidence flags surface low-confidence fields. Tuning on 5 reps gets accuracy where it needs to be.

Rates & resource taxonomies drift.

If "Project Manager" means something different in the 2024 catalog vs 2027, benchmarks compare apples to oranges.

Mitigation:   Catalog is versioned by year. Each project stores the catalog version it used. Benchmarks normalize before comparing.

Clockify mapping is messier than it looks.

One resource often books to multiple roles across multiple projects; project codes drift; non-billable categories pollute totals.

Mitigation:   Map-once-then-cache: Clockify project → fee record links and title pins are saved to the shared staff file, so a mapping fixed once holds for everyone. Unmapped entries surface as unattributed burn on the Profitability page for review.

Adoption — PEs may not use it.

A great tool that nobody opens is worth nothing. Especially if it duplicates effort.

Mitigation:   Make the calculator the path of least resistance for new proposals (better than Excel templates). Excel export keeps procurement happy. Make ingestion handle the historical pain so PEs aren't double-entering.

Confidential data & access.

Fee data and the rate grid are sensitive. The deployed app ships with neither — it pulls them from Box only after OAuth sign-in. Per-person filtering is currently client-side, so Box folder permission is the real boundary.

Mitigation:   Lock the Box folder to the trusted group; admin allowlist + per-project grants for everyone else. Server-side per-user filtering is the next hardening step for true project-level isolation.

Where we are, and what's next.

Phases 0–7 are live — author fees (fixed or NTE, with change orders, versions, broker splits and pass-through), ingest historicals, bulk-import the billing book, index and benchmark every project, analyse win/loss and discounting, project revenue firm-wide, compare it against the Budget / RF baselines in the Revenue Studio, track staffing load, and lay Clockify burn against the plan for margin by month — all Box-backed and multi-user, with a regression suite (tests.html) guarding the engine. Remaining: the formal accrual / flash output, a 90-day capacity view, utilization charts, and a two-way Salesforce sync so contract numbers write back automatically.
