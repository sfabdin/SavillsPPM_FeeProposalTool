01

Capture the fee where it's born.

Every fee starts as a matrix someone builds in the calculator. That's the source of truth — roles, rates, discount, phase split, monthly schedule. Authored once, saved to the database, and never typed into a spreadsheet again. You can't send a fee without it, so the data is captured by definition.

02

Let one number flow downstream.

That same record drives everything that comes after — monthly billing projections, accruals, the flash report, the P&L, fee-share splits, and the Salesforce intake. One number, entered once, reconciled everywhere. The output isn't just reporting to leadership; it's easing the burden on every leg of the process.

Decision · Storage

Where the data lives.

Honest tradeoffs · don't over-engineer Phase 1
Today · Phases 0–3

Browser localStorage + JSON file

Single-user prototype
  • Ships immediately, zero IT involvement
  • Works offline, no API keys
  • JSON export = bulletproof backup & portable record
  • Single browser, single user — no concurrent access
  • Cache clear destroys data unless backed up
  • No audit log, no permissions
Phase 7

Airtable (recommended)

Multi-user, shared, real database
  • Stand up in a day; schema matches our JSON record 1:1
  • Multi-user with permissions per PE
  • API + Zapier — easy to wire Clockify in later
  • Web UI as backup data-entry surface
  • ~$20–$25/user/month at our scale
  • Plan limits if we cross 50k records (we won't)
Phase 8+

Enterprise backend

When the firm needs SSO + integration
  • SharePoint Lists + Power Apps (if MSFT-shop)
  • Or custom Postgres + Node API for full control
  • Salesforce custom object if we go all-in on CRM
  • IT involvement required, weeks of setup
  • Migrate later once Airtable shape is proven

Watch-outs

Risks & how we mitigate.

Backtracking is a slog.

50–100 historical projects, each with roles + rates + phases + FTE matrices, is a real chunk of work — even with LLM extraction.

Mitigation:   Pilot with 10 manual entries to prove the schema, then unlock the ingestion studio for the rest. Two PEs × 1 hr/week × 8 weeks gets us to 50+.

LLM extraction will hallucinate.

Claude will get rates wrong, miscount FTE %, or fabricate roles on edge-case docs.

Mitigation:   Every extraction is reviewed in side-by-side UI before save. Confidence flags surface low-confidence fields. Tuning on 5 reps gets accuracy where it needs to be.

Rates & resource taxonomies drift.

If "Project Manager" means something different in the 2024 catalog vs 2027, benchmarks compare apples to oranges.

Mitigation:   Catalog is versioned by year. Each project stores the catalog version it used. Benchmarks normalize before comparing.

Clockify mapping is messier than it looks.

One resource often books to multiple roles across multiple projects; project codes drift; non-billable categories pollute totals.

Mitigation:   Map-once-then-cache: build a resource→role mapping table, surface unmapped entries weekly for human review. Phase 4 starts narrow (3–5 active projects), expands once mapping is reliable.

Adoption — PEs may not use it.

A great tool that nobody opens is worth nothing. Especially if it duplicates effort.

Mitigation:   Make the calculator the path of least resistance for new proposals (better than Excel templates). Excel export keeps procurement happy. Make ingestion handle the historical pain so PEs aren't double-entering.

Storage cost & migration cost.

Airtable is $20–25/user/month; if we add 20 users that's $5–6k/year. Migrating later to a custom backend is another sprint of work.

Mitigation:   Validate value with 3–5 power users on Airtable first. Schema-first design means migration is data-move, not rewrite. Costs ~$1.5k/year for that pilot.
